# 项目设计文档：健康测评获客漏斗 (Quiz Funnel)

## 一、 系统架构设计

### 1. 技术栈选型
*   **框架:** Next.js 14 (App Router) + React 18
*   **语言:** TypeScript (强类型约束，提升 AI 生成代码的准确率)
*   **样式:** Tailwind CSS + `clsx`/`tailwind-merge` (原子化 CSS，便于 AI 组合)
*   **动效:** Framer Motion (页面级过渡与微交互)
*   **状态管理:** Zustand + `persist` 中间件 (轻量，易于定义扁平的 Store)
*   **数据可视化:** D3.js (处理 Step 5 的复杂平滑曲线与面积图绘制，确保底层渲染的高级感)

### 2. 目录结构设计 (扁平化策略)
为了降低 AI 读取上下文的复杂度，避免深层嵌套，组件目录保持高度扁平。`components/ui` 存放无状态的原子组件，`components/quiz` 存放业务组件。

```text
├── app/
│   ├── layout.tsx         # 全局布局 (引入字体、统一样式)
│   ├── page.tsx           # 首页/落地页 (入口)
│   └── quiz/              # 问卷核心路由
│       ├── layout.tsx     # 基础样式容器
│       ├── page.tsx       # SPA 调度器与动画容器 (承载 Step 1-5)
│       └── NavigationButtons.tsx # 底部导航栏
├── components/
│   ├── ui/                # 扁平化原子组件 (AI 核心生成区)
│   │   ├── Button.tsx
│   │   ├── Card.tsx
│   │   ├── ProgressBar.tsx
│   │   └── Input.tsx
│   └── quiz/              # 业务组件
│       ├── StepLayout.tsx # 单步通用布局 (标题、副标题、动画包装)
│       ├── OptionList.tsx # 选择题列表
│       └── TrendChart.tsx # D3.js 驱动的趋势图封装
├── config/
│   └── quizFlow.ts        # 问卷流程配置 (配置驱动)
├── store/
│   └── useQuizStore.ts    # Zustand 全局状态
└── utils/
    ├── calculation.ts     # 纯函数：BMI、目标日期预测等
    └── validation.ts      # 纯函数：数据校验 (Zod Schema)
```

## 二、 核心功能模块设计

### 1. 状态管理模块 (Store)
使用 Zustand 维护全局状态，必须开启 `persist` 确保页面刷新后数据不丢失。
*   **设计原则:** 状态扁平化，避免深层嵌套对象，提供单一的 `setField` 方法。
*   **核心字段:** `gender`, `goal`, `unit` (公制/英制), `age`, `height`, `weight`, `targetWeight`, `activityLevel`, `direction` (动画方向 1 或 -1)。

### 2. 数据校验模块 (Validation)
特别是 Step 2 需要输入多项身体数据，必须保证数据的合法性。
*   **Schema 声明:** 采用轻量级的 `zod` 进行 Schema 定义，例如限制年龄 `18-100`，体重 `30-200kg` 等。
*   **交互反馈:** 用户输入失焦 (blur) 或点击下一步时触发校验，若不通过则阻止跳转，并在 Input 组件下方或内部显示红色提示及震动微动效。

### 3. 问卷引擎与单路由调度 (Single-Route SPA Quiz Engine)
采用**配置驱动（Config-Driven）与全局状态调度**的设计。为了实现业内顶级的丝滑过渡和极速响应，放弃传统的基于 URL 路径的动态路由 (`[step]`)，转而使用单一路由 (`/quiz`) 下的组件级替换。

*   **配置定义 (`config/quizFlow.ts`):** 包含每一步的 `id`, `type` (单选/数值输入/分析加载/结果页), `title`, `options`, `nextStep`, `prevStep` 等。
*   **单页调度器 (`app/quiz/page.tsx`):** 监听 Zustand 中的 `currentStepId`，根据配置表实时渲染对应的业务组件，完全消除网络请求带来的延迟。
*   **流转与方向控制 (Directional Routing):**
    *   点击“下一步”或“上一步”时，分别设置 Store 中的 `direction` 为 `1` 或 `-1`，并同步更新 `currentStepId`。
    *   借助于 `zustand/middleware` 的 `persist`，刷新页面时会根据缓存的 `currentStepId` 恢复进度。
*   **丝滑过渡:** 在 `app/quiz/page.tsx` 中使用 Framer Motion 的 `AnimatePresence` 监听 `currentStepId` 变化，配合 `mode="wait"` 和 `custom={direction}` 属性动态调整动画方向。
    *   **入场动画:** `x: direction * 50, opacity: 0` -> `x: 0, opacity: 1`
    *   **出场动画:** `x: direction * -50, opacity: 0`
    *   **弹性曲线:** `transition={{ type: "spring", stiffness: 300, damping: 30 }}`

### 3. Step 4: 假加载与情绪铺垫模块 (Fake Analysis)
这是提升漏斗转化率的关键模块，需要拦截路由并强制停留。
*   **生命周期控制:** 组件挂载时触发 `useEffect`，启动一个 3500ms 的 `setTimeout`，结束后调用 `router.push('/quiz/result')`。
*   **动态反馈:**
    *   **进度条:** 使用 Framer Motion 控制 `width` 从 `0%` 到 `100%`，设置 `duration: 3.5`，`ease: "easeInOut"`。
    *   **文案轮播:** 设定包含 3-4 条短语的数组（如："扫描体型数据...", "计算基础代谢...", "生成专属方案..."），每 800ms 切换一次索引。

### 4. Step 5: 结果预测与可视化模块 (Result & Paywall)
*   **数据计算 (`utils/calculation.ts`):** 抽离纯逻辑函数。根据基础代谢率（BMR）公式和用户目标（减脂/增肌），计算出每周合理的体重变动值，从而推算出**达标所需周数**和**预计达标日期**。
*   **高级感图表 (`TrendChart.tsx`):**
    *   摒弃笨重的图表库，直接使用 **D3.js** 控制核心渲染循环。
    *   将 React 的状态传递给 D3.js 绘图函数。使用 `d3.line().curve(d3.curveBasis)` 绘制极其平滑的曲线。
    *   添加下方的 SVG 渐变填充 (`<linearGradient>`) 提升欧美高级 App 质感。
    *   移除所有的内部网格线，只保留首尾两个关键数据点的高亮标注。
*   **付费卡片 (Subscription Card):** 悬浮在图表下方，使用高对比度设计，包含一个强引导的呼吸灯效果 CTA (Call to Action) 按钮。

## 三、 UI 审美与设计规范

为了达到“欧美主流 App 的高级感”，需要在 Tailwind 中预设严格的设计规范：

1.  **多端适配策略 (Mobile-First):**
    *   **核心策略:** 整体布局使用 `max-w-md mx-auto min-h-screen relative shadow-2xl overflow-hidden`。在移动端铺满屏幕，在 PC 端居中显示，像一个内嵌的 App 窗口（类似 Web App），避免在大屏上内容显得过于松散。
    *   **安全区:** 考虑移动端异形屏，底部按钮区域预留 `pb-safe` 空间。
2.  **色彩与主题 (Color Palette):**
    *   使用深色模式 (Dark Mode) 或高对比度的浅色主题。建议主色调 (`primary`) 采用高饱和度的色彩（如电光蓝、珊瑚红或薄荷绿），搭配中性灰阶背景。
3.  **视觉层级 (Typography):**
    *   主标题：`text-3xl font-extrabold tracking-tight text-gray-900` (或深色模式下的 `text-white`)
    *   副标题：`text-base font-medium text-gray-500`
4.  **微交互 (Micro-interactions):**
    *   所有的按钮和选项卡 (Option Card) 必须有 `hover:scale-[1.02] active:scale-[0.98]` 的物理反馈。
    *   选中状态使用明显的边框和微弱的背景色进行高亮（如 `ring-2 ring-primary bg-primary/10`）。

## 四、 部署与交付规范

1.  **平台选择:** 推荐使用 Vercel 进行零配置部署，天然适配 Next.js App Router。
2.  **构建要求:** 确保本地 `npm run build` 无 TypeScript 类型报错，且 ESLint 检查通过。
3.  **环境变量:** 本项目理论上无需复杂的后端环境变量。若引入了外部 API（如埋点或 AI），需在 Vercel 面板中正确配置。

## 五、 AI 辅助开发规范 (AI Collaboration Guidelines)

为了高效驱动 AI（如 Cursor/Copilot）生成符合要求的代码，并避免代码发散，必须遵循以下协作原则：

1.  **按职责拆分 Prompt:**
    *   **错误示范:** “帮我写一个第二步的表单页面，要有年龄身高体重，还要能校验，顺便把切换公制英制做了。” (过于庞杂，AI 容易产生冗余或错误逻辑)
    *   **正确示范:** 
        *   第一轮：“请使用 Tailwind 和 clsx 写一个纯 UI 组件 `Input.tsx`，支持传入 error 状态并显示红框。”
        *   第二轮：“使用 zod 定义年龄、身高、体重的校验 schema。”
        *   第三轮：“在 Step 2 的业务组件中，引入 `useQuizStore` 和刚才的 `zod schema`，实现表单渲染和校验拦截。”
2.  **严格限定依赖库:** 在 Prompt 中明确告知 AI 当前项目使用的技术栈：“只使用 Zustand, Framer Motion, Tailwind CSS 和 D3.js。严禁引入 Recharts、Formik 等其他大体积库。”
3.  **提供明确的上下文:** 让 AI 修改某个文件前，先让它读取 `quizFlow.ts` 和 `useQuizStore.ts`，确保其生成的代码与全局状态和路由配置相匹配。
