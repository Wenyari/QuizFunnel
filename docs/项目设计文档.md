# 项目设计文档：健康测评获客漏斗 (Quiz Funnel)

## 一、 系统架构设计

### 1. 技术栈选型
*   **框架:** Next.js 14 (App Router) + React 18
*   **语言:** TypeScript (强类型约束，提升 AI 生成代码的准确率)
*   **样式:** Tailwind CSS + `clsx`/`tailwind-merge` (原子化 CSS，便于 AI 组合)
*   **动效:** Framer Motion (页面级过渡与微交互)
*   **状态管理:** Zustand + `persist` 中间件 (轻量，易于定义扁平的 Store)
*   **数据可视化:** D3.js (处理 Step 5 的复杂平滑曲线与面积图绘制，确保底层渲染的高级感)

### 2. 目录结构设计 (扁平化策略)
为了降低 AI 读取上下文的复杂度，避免深层嵌套，组件目录保持高度扁平。`components/ui` 存放无状态的原子组件，`components/quiz` 存放业务组件。

```text
├── app/
│   ├── layout.tsx         # 全局布局 (引入字体、统一样式)
│   ├── page.tsx           # 首页/落地页 (入口)
│   └── quiz/              # 问卷核心路由
│       ├── layout.tsx     # 包含 AnimatePresence 的过渡容器
│       └── [step]/page.tsx# 动态路由，承载 Step 1-5
├── components/
│   ├── ui/                # 扁平化原子组件 (AI 核心生成区)
│   │   ├── Button.tsx
│   │   ├── Card.tsx
│   │   ├── ProgressBar.tsx
│   │   └── Input.tsx
│   └── quiz/              # 业务组件
│       ├── StepLayout.tsx # 单步通用布局 (标题、副标题、动画包装)
│       ├── OptionList.tsx # 选择题列表
│       └── TrendChart.tsx # D3.js 驱动的趋势图封装
├── config/
│   └── quizFlow.ts        # 问卷流程配置 (配置驱动)
├── store/
│   └── useQuizStore.ts    # Zustand 全局状态
└── utils/
    └── calculation.ts     # 纯函数：BMI、目标日期预测等
```

## 二、 核心功能模块设计

### 1. 状态管理模块 (Store)
使用 Zustand 维护全局状态，必须开启 `persist` 确保页面刷新后数据不丢失。
*   **设计原则:** 状态扁平化，避免深层嵌套对象，提供单一的 `setField` 方法。
*   **核心字段:** `gender`, `goal`, `unit` (公制/英制), `age`, `height`, `weight`, `targetWeight`, `activityLevel`。

### 2. 问卷引擎与路由模块 (Quiz Engine)
采用**配置驱动（Config-Driven）**的设计。不要将每一步的 UI 写死在不同的页面里，而是通过一份配置表来渲染。

*   **配置定义 (`config/quizFlow.ts`):** 包含每一步的 `id`, `type` (单选/数值输入/分析加载/结果页), `title`, `options` 等。
*   **动态路由 (`app/quiz/[step]/page.tsx`):** 根据 URL 参数读取配置，渲染对应的组件。
*   **丝滑过渡:** 在 `app/quiz/layout.tsx` 中使用 Framer Motion 的 `AnimatePresence`，配合 `mode="wait"`。
    *   **入场动画:** `x: 20, opacity: 0` -> `x: 0, opacity: 1`
    *   **出场动画:** `x: -20, opacity: 0`
    *   **弹性曲线:** `transition={{ type: "spring", stiffness: 300, damping: 30 }}`

### 3. Step 4: 假加载与情绪铺垫模块 (Fake Analysis)
这是提升漏斗转化率的关键模块，需要拦截路由并强制停留。
*   **生命周期控制:** 组件挂载时触发 `useEffect`，启动一个 3500ms 的 `setTimeout`，结束后调用 `router.push('/quiz/result')`。
*   **动态反馈:**
    *   **进度条:** 使用 Framer Motion 控制 `width` 从 `0%` 到 `100%`，设置 `duration: 3.5`，`ease: "easeInOut"`。
    *   **文案轮播:** 设定包含 3-4 条短语的数组（如："扫描体型数据...", "计算基础代谢...", "生成专属方案..."），每 800ms 切换一次索引。

### 4. Step 5: 结果预测与可视化模块 (Result & Paywall)
*   **数据计算 (`utils/calculation.ts`):** 抽离纯逻辑函数。根据基础代谢率（BMR）公式和用户目标（减脂/增肌），计算出每周合理的体重变动值，从而推算出**达标所需周数**和**预计达标日期**。
*   **高级感图表 (`TrendChart.tsx`):**
    *   摒弃笨重的图表库，直接使用 **D3.js** 控制核心渲染循环。
    *   将 React 的状态传递给 D3.js 绘图函数。使用 `d3.line().curve(d3.curveBasis)` 绘制极其平滑的曲线。
    *   添加下方的 SVG 渐变填充 (`<linearGradient>`) 提升欧美高级 App 质感。
    *   移除所有的内部网格线，只保留首尾两个关键数据点的高亮标注。
*   **付费卡片 (Subscription Card):** 悬浮在图表下方，使用高对比度设计，包含一个强引导的呼吸灯效果 CTA (Call to Action) 按钮。

## 三、 UI 审美与设计规范

为了达到“欧美主流 App 的高级感”，需要在 Tailwind 中预设严格的设计规范：

1.  **极简留白 (Spacing):** 整体布局使用 `max-w-md mx-auto px-6 py-8` 限制宽度，模拟移动端原生体验。组件间距使用宽松的倍数（如 `gap-6`, `mb-8`）。
2.  **视觉层级 (Typography):**
    *   主标题：`text-3xl font-extrabold tracking-tight text-gray-900`
    *   副标题：`text-base font-medium text-gray-500`
3.  **微交互 (Micro-interactions):**
    *   所有的按钮和选项卡 (Option Card) 必须有 `hover:scale-[1.02] active:scale-[0.98]` 的物理反馈。
    *   选中状态使用明显的边框和微弱的背景色进行高亮（如 `ring-2 ring-primary bg-primary/5`）。
